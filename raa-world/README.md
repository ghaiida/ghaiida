# راء وورلد | RAA WORLD

**«حوّلي درسكِ إلى مغامرة تعليمية!»** — قالب ألعاب تعليمية ذكي من **منصة راء**. تخصّص فيه المعلمة اللعبة لأي مادة وأي صف دون برمجة، ثم تشارك رابطها مع طالباتها.

---

## ما الذي يعمل فعلًا الآن

| الميزة | الحالة |
|---|---|
| حساب معلمة (تسجيل ودخول وخروج) وحفظ الألعاب في قاعدة بيانات على الخادم | يعمل، ومختبر |

| حفظ تلقائي للمسودة، وزر «حفظ المسودة»، وتنبيه عند تعديل اللعبة من جهازين | يعمل |

| رابط مشاركة ثابت لكل لعبة، ونسخ الرابط، ورمز QR قابل للتنزيل | يعمل |

| ألعاب تجريبية عامة دون حساب: `/demo/science` و `/demo/math` | يعمل |

### ما لم يُنفَّذ (بصراحة)

- **القالب الرابع «تحدي الكنز»**: لم يُنفَّذ، ولا يظهر في الواجهة. البنية جاهزة لإضافته (انظري «إضافة قالب جديد» أدناه).
- **استخراج الأسئلة من PDF**: لم يُنفَّذ ولا يوجد له زر في الواجهة. البديل العملي هو نموذج Excel.
- **استعادة كلمة المرور بالبريد**: غير موجودة لأنها تحتاج إلى خدمة إرسال بريد. البديل المؤقت أن يعيد الدعم تعيينها بالأمر `npm run admin:reset-password -- email كلمة-جديدة`.
- **تصحيح الإجابات** يتم في متصفح الطالبة، ولهذا تصل إجابات اللعبة المنشورة إلى المتصفح. يعيد الخادم حساب الدرجة من قواعد اللعبة ويتجاهل الأسئلة غير الموجودة فيها، لكن طالبة ذات خبرة تقنية تستطيع نظريًا التلاعب بنتيجتها. هذا مقبول للتقويم البنائي الصفي، أما الاختبارات الرسمية فتحتاج إلى تصحيح على الخادم (تطوير مستقبلي).
- **ملفات Excel القديمة (.xls)** غير مدعومة، ويُطلب من المعلمة حفظ الملف بصيغة ‎.xlsx أو CSV.

## إجابات مباشرة

- **هل الحفظ دائم؟** نعم. كل شيء محفوظ في قاعدة بيانات SQLite على الخادم، داخل المجلد `DATA_DIR`، ويبقى ما دام هذا المجلد على قرص دائم. على الاستضافة يجب ربط **قرص دائم** (Persistent Disk)، وإلا تُمسح البيانات عند كل إعادة نشر.
- **هل رابط المشاركة يعمل على أجهزة أخرى؟** نعم، بعد نشر الخادم على الإنترنت. في الاختبار فُتح الرابط في جلسة متصفح منفصلة بمقاس جوال، ولُعبت اللعبة ووصلت النتيجة. أثناء التشغيل المحلي (`localhost`) يعمل الرابط على جهاز التطوير فقط.
- **هل النتائج تُحفظ فعلًا؟** نعم، عندما تفعّل المعلمة «تسجيل نتائج الطالبات» ثم تنشر. تظهر النتائج في صفحة «نتائج الطالبات» ويمكن تصديرها. إذا كان التسجيل معطّلًا لا يُرسل شيء، ولا تعرض اللعبة للطالبة رسالة «وصلت نتيجتكِ» إلا بعد تأكيد الخادم.
- **هل تختلط ألعاب المعلمات؟** لا. لكل لعبة معرّف مستقل ومسودة ونسخة منشورة خاصة بها، ولا تستطيع معلمة فتح لعبة معلمة أخرى أو تعديلها. هذا مختبر آليًا.

## التشغيل محليًا

المتطلبات: Node.js 22.13 أو أحدث (يستخدم المشروع قاعدة SQLite المدمجة في Node، فلا حاجة إلى تثبيت قاعدة بيانات).

```bash
cd raa-world
npm install
npm run dev          # الواجهة على http://localhost:5173 والخادم على 8787
```

للتشغيل كما في الإنتاج:

```bash
npm run build
npm start            # http://localhost:8787  (البيانات في ./data)
```

### الاختبارات

```bash
npm test             # اختبارات المحرك والاستيراد والـ API: العزل، والمسودة مقابل المنشور، والنتائج
npm run typecheck
npm run e2e          # السيناريو الكامل في متصفح حقيقي (يتطلب خادمًا يعمل على 8787)
```

يُنفّذ `npm run e2e` السيناريو المطلوب كاملًا: إنشاء لعبة علوم بخمسة أسئلة يدويًا، وقالب النجوم، والمعاينة واللعب، والحفظ والنشر، ثم لعب طالبة من الرابط على جهاز آخر (محاكاة جوال) ووصول النتيجة. بعد ذلك ينشئ لعبة رياضيات بقالب المتاهة عبر استيراد CSV يحتوي صفًّا خاطئًا عمدًا، ويتحقق من عدم اختلاط الأسئلة والإعدادات، ومن أن المسودة لا تصل إلى الطالبات قبل النشر، ويجرّب قالب البوابات، ويوقف النشر. تُحفظ لقطات الشاشة في `e2e/out/`.

## النشر على الإنترنت

### الخيار الموصى به: Render

1. ارفعي المستودع إلى GitHub.
2. من Render اختاري **New → Blueprint**، ثم اختاري المستودع، وحدّدي مجلد الجذر `raa-world` (يُقرأ منه `render.yaml`).
3. سيُنشأ تلقائيًا:
   - خدمة ويب Node 22 بأمر البناء `npm ci --include=dev && npm run build` وأمر التشغيل `npm start`.
   - **قرص دائم** بحجم 1GB على `/var/data`، و`DATA_DIR=/var/data`. القرص يتطلب خطة مدفوعة (Starter أو أعلى)؛ في الخطة المجانية تُمسح البيانات.
4. اربطي نطاقًا خاصًّا (مثل `play.raa.sa`) من إعدادات الخدمة، وسيُفعَّل HTTPS تلقائيًا.

### أي استضافة أخرى

يوجد `Dockerfile`. اربطي مجلدًا دائمًا بالمسار `/data`:

```bash
docker build -t raa-world .
docker run -p 8787:8787 -v raa-data:/data raa-world
```

### متغيرات البيئة

| المتغير | الوظيفة |
|---|---|
| `DATA_DIR` | مجلد قاعدة البيانات (يجب أن يكون على قرص دائم) |
| `PORT` | منفذ الخادم (الافتراضي 8787) |
| `NODE_ENV=production` | يجعل ملف تعريف الجلسة (cookie) آمنًا عبر HTTPS فقط |
| `REQUIRE_ACTIVATION_CODE=true` | يجعل إنشاء الحساب مشروطًا برمز تفعيل (للبيع) |

**النسخ الاحتياطي:** قاعدة البيانات ملف واحد هو `raa-world.sqlite` (مع ملفي `-wal` و`-shm`). انسخيه دوريًا، ويفضّل استخدام لقطات القرص من لوحة الاستضافة.

**قبل الإطلاق التجاري:** أضيفي صفحتي سياسة الخصوصية والشروط، وخدمة بريد لاستعادة كلمة المرور، ونسخًا احتياطيًا آليًا.

## تجهيز المنتج للبيع في متجر سلة

المنتج خدمة سحابية (اشتراك أو ترخيص استخدام) وليس ملفًا يُنزَّل. الطريقة الأبسط المدعومة الآن هي **رموز التفعيل**:

1. **فعّلي رموز التفعيل على الخادم:** اضبطي `REQUIRE_ACTIVATION_CODE=true`. بعدها لا يُنشأ حساب إلا برمز صالح، ويُستخدم كل رمز مرة واحدة.
2. **ولّدي دفعة رموز** على الخادم (من Render: تبويب Shell):
   ```bash
   npm run codes:generate -- 100 "دفعة سلة 1"
   ```
   يُنشأ ملف CSV بالرموز داخل `DATA_DIR`.
3. **أنشئي المنتج في سلة** من نوع المنتجات الرقمية التي تُسلَّم فيها **أكواد أو بطاقات رقمية**، ثم ارفعي الرموز ليُرسل كل رمز تلقائيًا لمشترية واحدة. تحققي من اسم هذا النوع في لوحة سلة الحالية، فقد تختلف التسمية.
4. **اكتبي في وصف المنتج ورسالة ما بعد الشراء:** رابط المنصة، مثل `https://play.raa.sa/register`، وخطوات إنشاء الحساب بالرمز، ومقطعًا قصيرًا يشرح الاستخدام، ومعلومات التواصل مع الدعم.
5. **أضيفي إلى صفحة المنتج:** صورًا من `e2e/out/` أو لقطات جديدة، ورابطي اللعبتين التجريبيتين `/demo/science` و`/demo/math` لتجربة المشترية قبل الشراء.
6. **مستقبلًا:** الربط الآلي مع سلة (Webhook عند اكتمال الطلب يولّد الرمز ويرسله) يحتاج إلى تطبيق في منصة شركاء سلة، وهو غير منفّذ حاليًا.

الرمز الحالي يمنح وصولًا غير محدود بمدة. للاشتراك السنوي يلزم إضافة تاريخ انتهاء للترخيص (حقل في جدول `licenses` وفحص عند الدخول)، وهي إضافة صغيرة.

## البنية التقنية

```
raa-world/
  shared/        ← المنطق المشترك بين المتصفح والخادم (دون واجهة)
    schema.ts      عقود البيانات (zod): اللعبة = قالب + بيانات + أسئلة + إعدادات
    engine.ts      محرك اللعب: اختيار الأسئلة وترتيبها، والتصحيح، والنقاط، وقواعد الصعوبة
    maze.ts        توليد المتاهات ومسار الحل ونقاط التفتيش
    importer.ts    قراءة صفوف Excel/CSV والتحقق منها، ونموذج الأعمدة
    validation.ts  فحوص «جاهزة للنشر»
    stats.ts       حساب النتائج والأسئلة الأصعب والمفاهيم
    samples.ts     مثالا العلوم والرياضيات
  server/        ← Express + SQLite (node:sqlite)
    app.ts         الـ API: الحسابات، والألعاب (مسودة/منشور)، والصور، واللعب العام، والنتائج
  client/src/    ← React + TypeScript (Vite)
    editor/        لوحة المعلمة بخطواتها الست
    player/        تجربة الطالبة: GamePlayer (المؤقت، والنقاط، وبطاقة السؤال، والنتيجة)
      templates/   StarsAdventure · MazeQuest · GatesChallenge
  tests/         ← اختبارات Vitest
  e2e/           ← سيناريو المتصفح الكامل
```

**الفصل المطلوب في المواصفات:**

1. **محرك اللعبة** (`shared/engine.ts` و`GamePlayer`): التصحيح والنقاط والمؤقت والمحاولات والتسجيل، وهو مشترك بين كل القوالب.
2. **قالب اللعبة** (`player/templates/*`): يحدد شكل التحدي وقواعده فقط، ويطلب الأسئلة من المحرك عبر `ask()`.
3. **المحتوى التعليمي** (`questions` داخل وثيقة اللعبة).
4. **إعدادات المعلمة** (`meta` و`settings`).
5. **بيانات كل لعبة**: صف مستقل في جدول `games` بمعرّف خاص، يحوي `draft` (المسودة) و`published` (ما تلعبه الطالبات)، ولا تنتقل المسودة إلى النسخة المنشورة إلا عند النشر.

### إضافة قالب جديد (مثل «تحدي الكنز»)

1. أضيفي المعرّف `'treasure'` إلى `TEMPLATE_IDS` في `shared/schema.ts`.
2. أضيفي وصفه في `TEMPLATES` بملف `shared/catalog.ts`، وقواعد الصعوبة في `DIFFICULTY_RULES` بملف `shared/engine.ts`، والتعليمات للطالبة في `player/words.ts`.
3. أنشئي مكوّنًا في `player/templates/` يستقبل `TemplateProps`، ويستدعي `ask(question, {...})` لكل سؤال، ثم `onComplete()` في النهاية.
4. سجّليه في `TEMPLATE_COMPONENTS` بملف `GamePlayer.tsx`، وأضيفي رسمه في `ui/TemplateArt.tsx`.

لا يلزم تغيير الخادم ولا قاعدة البيانات ولا المحتوى، وتستطيع أي لعبة قائمة التبديل إلى القالب الجديد.

### الهوية البصرية

اسم المنصة والمنتج والشعار النصّي موجودة في `client/src/brand.ts`، والألوان في `client/src/styles/app.css` (لوحة المعلمة) وفي `THEMES` بملف `shared/catalog.ts` (ألوان الألعاب). العلامة الحالية مؤقتة (حروف «راء» في مربع ملوّن)، وتُستبدل بشعار منصة راء الرسمي عند توفره. الخطّان Tajawal وCairo مضمّنان في المشروع، فلا يحتاج إلى خدمات خطوط خارجية.
